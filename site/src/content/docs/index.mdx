## Why Beacon?

You're building with AI agents — Claude Code, Cursor, Codex, Gemini CLI. After a few weeks, your repo has 47 markdown files in random folders, three versions of the same plan, ADRs duplicated across `/docs`, `/notes`, and `/decisions`, no `CLAUDE.md` or `.cursorrules` telling agents where new docs should go, and a graveyard of "is this still relevant?" content nobody dares delete.

**Beacon ships one opinionated convention and a CLI that enforces it.** AI agents stop creating docs in random places. Humans stop hunting for "the latest version." Reviews stop devolving into "should this be here?"

<CardGrid>
  <Card title="🗂️ Structure" icon="document">
    6 core folders every project needs + 6 opt-in add-ons (`compliance`, `business`, `modules`, `integrations`, `operations`, `roadmaps`).
  </Card>
  <Card title="🏷️ Naming" icon="information">
    Filename suffix encodes type (`.plan.md`, `.adr.md`), folder encodes status (`_archive/`). No more `PLAN_v2_FINAL.md`.
  </Card>
  <Card title="🤖 AI rule files" icon="setting">
    Generates `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`, `.cursor/rules/beacon.mdc` from a single source. Every AI agent gets rules in its preferred format.
  </Card>
  <Card title="🚨 Linter" icon="approve-check">
    11 rules validate structure, naming, and AI-file sync. CI-friendly with `--strict` and `--json`.
  </Card>
</CardGrid>
